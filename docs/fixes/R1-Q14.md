## 改动

`tools/build-art.js:37-44` 的加载顺序把 root 文件**排在最后**（注释写明是刻意的并发保护），
所以对同名的 17 个 id，`art/scenes.js` 的注册总是覆盖地区分册 —— 后者对画面**完全无效**。
本改动只删这 17 个 `ART.scenes['<id>'] = function () { … };` span，别的函数（含地区分册**独有**的 13 个 id 与全部 helper）一律不动。

### ⚠️ 对原稿一处数字的更正

原稿称"约 **1.9 MB** 永不生效的美术代码"。实测这 17 份 span 合计 **32 KB**：
`art/` 目录里最大的文件是 `ui_00_crowd_stamps.js`（1 694 496 B），与 scenes 无关；
`scenes_*.js` 四个文件加起来也只有 76 KB。**1.9 MB 这个数量级对不上**（大概是把整个分册文件、
或把烘焙产物里的 base64 当成了死代码）。结论不变（确实是死代码、确实是两个真相），但数字要按实测写。

**为什么"`git status --short assets/generated` 无变化"这条按字面没达成**：删掉 17 份注册会让这几个 id
的**注册顺序**改变（原本由地区分册先创建 key），而烘焙器用**进程级计数器**给
`linearGradient/radialGradient` 编号（`sky132`、`mist68`、`vig69`…），顺序一挪，编号就整体位移。
结果是 36 个产物"只差内部 id 编号、归一化后逐字节相同"（`tmp/q14-normalize.js` 实测），另外 18 个是 Q13 的真实内容改动。

因此本条的"零回归"结论是：**画面内容零变化**（编号是 SVG 内部引用，成对生成、自洽），
而不是**字节零变化**。验收组若坚持字节判据，需要先允许改 `tools/build-art.js`（本轮被裁决为不可动）让 `uid` 编号与注册顺序解耦。
