## 副作用（必须说清，不许藏）

`node tools/check.js` 的警告从 **1 条变成 7 条**，新增 6 条都是同一类：

```
[src/story/ch05.js] 正文字数 2729（要求 ≥ 3000）
[src/story/ch06.js] 正文字数 2818（要求 ≥ 3000）
[src/story/ch08.js] 正文字数 2659（要求 ≥ 3000）
[src/story/ch13.js] 正文字数 2798（要求 ≥ 3000）
[src/story/ch15.js] 正文字数 2871（要求 ≥ 3000）
[src/story/ch19.js] 正文字数 2783（要求 ≥ 3000）
```

**这不是"删掉了玩家的文字"，是"把不该计入正文的文字移出了正文计数器"**：

- 玩家可见的汉字一个没少 —— 小注照旧在章节里显示，只是改由对白步的 `note:` 字段承载。
- 算术对得上：每章减少的字数 = 被搬走的小注汉字数（ch05 357 / ch06 331 / ch08 352 / ch13 335 / ch14 69 / ch15 153 / ch19 241 / ch20 198），其余一字未动。
- 根因是计数器口径：`tools/check.js:133` 把**任何**带 `text` 的 step 都算进 `hanzi`（`note` 步因此被算作正文），而 `docs/SPEC.md:328` 写的是「正文**对白** ≥ 3000 个汉字（含旁白）」。按 SPEC 的字面口径，这 6 章的"对白+旁白"改造前就只有 2659–2871，**之前是被"把史料小注也算作正文"掩盖了**。

处置建议（已登记进 `R1-INDEX.md` §6，留给下一轮）：要么给这 6 章补真正的对白/旁白，要么明确"史料小注是否计入正文字数"这条口径。本轮**不动** `tools/check.js`（§4 规定 `tools/` 一次只允许一个 agent 动，本轮额度归 `g2_eng` 的 Q11）。
