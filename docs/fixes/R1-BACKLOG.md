**现象**：我跑 `node tools/check.js` 时（18:2x）多出 6 条「正文字数不足 3000」警告。它们

（其余 12 章两边完全一致；当时正在改这些文件的是 R1-Q05 的解决人。）

**根因**：`docs/SPEC.md` §2 要求「每章正文 ≥3000 汉字」，而 `tools/check.js:80` 的

只 `warn`、不 `err` —— 于是**仍然打印「检查通过。」、退出码 0**，很容易被当成"全绿"放过去。

**注意 HEAD 本身没问题**：HEAD 合计正好 **61043 汉字**，与 `R1-INDEX.md` §0 记的基线

## 4. `tools/e2e-run.js` 参数非法时，报错指向"章节不合格"而不是"参数错了"

误用一次就会得到误导性结论。实测（只跑一章，2.7 秒）：

```powershell
node tools/e2e-run.js abc 8 600000 ch01; "exit=$LASTEXITCODE"
```

```
通关验证：每章自动点第 NaN 个选项，步间隔 8ms，虚拟时间上限 600000ms

章   标题                步数  走完  选项  背景  CG   报错
ch01  于都河畔                4000   ✘     0     2    0  0
合计：1 章 / 4000 步 / 实际渲染的 CG 0 张次

不合格章节：
  · ch01：走完=false，步数=4000
exit=2
```

`pickIndex` 变成 `NaN` → 选项面板永远点不到 → 每章跑满步数上限，然后把**章节**判为不合格。
退出码是 2（非 0，这点是对的），但"不合格章节"这四个字很容易让人以为**游戏**坏了。
建议：`pickIndex` 非正整数时直接打印用法并退出（一行校验）。
