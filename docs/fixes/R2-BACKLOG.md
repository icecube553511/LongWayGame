## B01（P2 · tools）只跑单章时，`e2e-run.js` 的收尾文案仍声称跑完了 20 章

**现象**

```powershell
node tools/e2e-run.js 1 8 600000 ch01
```

```
合计：1 章 / 1173 步 / 实际渲染的 CG 1 张次
全部 20 章均从头走到结尾，且无 JS 报错。     <-- 与实际不符（只跑了 1 章）
```

那句尾注是硬编码的，没有按实际跑了几章来分支。**功能没坏**（退出码、逐章判定都对），
坏的是维护者读到的那句话 —— 用 `ONLY`（第 5 个参数）只跑几章时会得到超出实际的结论。

**建议修法**：尾注按 `ONLY.length` 或实际跑的章数选文案；只跑部分章节时明确写
「本次只跑了 N 章：…」。

**发现于**：`R2-E05` 的回归验证。

## B02（P2 · tools）浏览器探针可能长时间挂住不返回

**现象（实测）**

```powershell
node tools/e2e-run.js     # 同一命令连续跑第 3 次时挂住 6 分钟以上，无任何输出
```

当时残留进程：`node tools/e2e-run.js`（PID 17504）+ 其无头 Edge 子树，由组长手动终止。
`docs/issues/R2-engine.md` 的 R2-E06 节记录的是同一族问题的**文件残留**面
（`_e2e_*.html` 不被异常路径清理）；这里补的是**进程挂住**面。

**影响**：任何自动化/agent 裸跑探针都可能永久卡住 —— 本轮有两个 agent 因此失去产出。

**建议修法**：给探针加整体看门狗（例如 `setTimeout(..., budget + 富余).unref()` 到点打印诊断并
`process.exit(3)`），并在文档里写明"跑探针必须带超时"。

**发现于**：`R2-E04` 的回归验证（见 `docs/fixes/R2-E04.md` 的「未完成 / 降级」第 2 条）。
