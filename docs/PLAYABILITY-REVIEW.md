# 《长征·万水千山》可玩性评估与参与度改造方案

评审对象：本仓库当前状态（HEAD `1ab05ed`）。
评审方式：静态读码 + 剧本 DSL 全量解析 + 无头浏览器实机截屏。
交付对象：后续执行的 agent。
结论等级：**叙事合格，机制缺位**。内容资产（文笔、美术、史料）已经到位，但"游戏"那一半目前是装饰。改造重点不在写更多字，而在**让已有的 60 个选项开始记账**。

---

## 0. 一句话结论

这是一本写得很好的小说，配了一套看起来像游戏的外壳。问题不在内容量的多少，而在于**玩家做出的每一个选择，都在 100 字之后被彻底遗忘**——连游戏自己在第一章提出的问题，到终章都没有再问过一次。

最锋利的证据：

`src/story/ch01.js` 第 2 个选项问玩家「你要离开后方医院了。这些带不走的人，你还能为他们做什么？」，其中一项是「把他们的名字记在心里，一个一个念一遍」→ 写入 `flag.remember_names = true`。

**全剧 20 章、6642 步、61,177 汉字，没有任何一处读过这个变量。** 而终章第 3 个选项偏偏又问「你想对那个孩子说的那句话」→ 写入 `flag.ch20_words_to_boy`，同样永远没有下文。

这不是笔误，是**结构性缺失**：引擎有状态、有存档、有条件分支，但没有任何机制要求剧本去读它。于是 20 章走完，玩家唯一的收获是一屏三个字的评语。

## 1. 现状基线（全部为实测值，可复现）

### 1.1 内容规模

| 项 | 实测 | 备注 |
|---|---|---|
| 章节 | 20 | 全绿通过 `node tools/check.js` |
| 总步数 | 6,642 | 平均 332 步/章 |
| 对白/旁白/独白步数 | 4,942 | 平均每句 12 汉字 |
| 正文汉字 | 61,177 | 61,177 ÷ 300~450 字/分 ≈ 135–202 分钟纯阅读 |
| 首次通关真实耗时 | 估 3.5–5 小时 | 含点击节奏（4,942 句 × 3 秒 ≈ 247 分钟） |
| 选项 | 60 | **每章恰好 3 个**，无一例外 |
| 史料档案 | 81 | 每章 4–5 条 |
| 背景 / CG / 立绘 | 30 / 30 / 280 | 立绘含 174 张 AI PNG |
| 人物 | 35 | 23 史实 + 8 虚构 + 4 群体 |
| 程序化 BGM / 音效 | 12 / 14 | 无音频文件 |
| 已跟踪仓库体积 | 76.8 MB | 其中立绘 PNG 55.9 MB |

### 1.2 玩法机制

| 机制 | 现状 |
|---|---|
| 状态 | `morale` / `trust` / `hope`，各 clamp 0–100，初值 60/50/55 |
| 存档 | 6 槽 + 自动存档（每 14 步），localStorage，前缀 `lw_` |
| 分支 | `label` / `goto` / `if` / `choice.goto` |
| 收集 | 人物图鉴 35、史料档案 81、插画画廊 50 |
| 结局 | 单屏，按三数值平均分三档：≥75「钢铁洪流」/ ≥60「星火燎原」/ 其余「血染征途」 |
| 结局可达区间 | 全最优 = 三项 100（avg 100）；全最差 = 16/1/36（avg 18）；初值 avg 55 |

### 1.3 三个数值的真相

解析全部 20 章的 `if` 条件后，统计条件里出现过的变量名：

| 变量 | 被选项写入 | 被任何 `if` 读取 |
|---|---|---|
| `morale` | 是（多章） | **否** |
| `trust` | 是（多章） | **否** |
| `hope` | 是（多章） | **否** |

**三条数值条在整个游戏过程中，除了改变自身的宽度和颜色，不产生任何影响。** 唯一的读者是终章的 `showResult()`。玩家大约在第二章就能察觉这件事，而屏幕右上角那三条一直在闪光的进度条，会持续 4 小时提醒他"这不重要"。

### 1.4 选项记账情况

全量解析 60 个选项的 `set`：

- 选项共写入 **95** 个变量
- 被任何 `if` 读过的：**52** 个
- **写过但全剧没有任何 `if` 读取：43 个（45%）**

从未被读回的 43 个里，有相当一部分是剧本刻意埋的情感伏笔，例如：`remember_names`（记名字）、`promise_hope`（给希望的承诺）、`promise_honest`（说实话的承诺）、`ch19_words_to_mei`（想对何晓梅说的话）、`ch20_words_to_boy`（想对那个孩子说的话）、`ch15_token_carrier`（顶针在谁手里）、`hat_given`（把帽子给了谁）。

**这些正是本作最想写的东西，也正好是丢得最干脆的东西。**

### 1.5 分支的真实分量

| 指标 | 实测 |
|---|---|
| 用 `label`/`goto` 做真分支的章 | **4 / 20**（仅 ch09–ch12） |
| 其余 16 章的 `label` 数 | 0 |
| 条件分支内的汉字占全章比例 | 2.0% – 24.1%，中位 ≈ 6% |
| 选项之后紧跟 `if` 反应的 | 29 / 60（覆盖 17 章） |
| 该反应块的汉字数 | 中位 104（约 4–6 句），最小 54，最大 181 |

也就是说：**一半的选项有反应，但反应在 100 字内结束，随后剧情无条件合流。** 分支不是没有，而是"没有下游"。

### 1.6 选项的取舍结构

- 60 个选项中，**31 个（52%）的全部选项在三条数值上都不为负** → 没有代价，只是挑哪种奖励。
- 存在仪表效果完全等价的选项对：0 个（这点做得好，每个选项都有数值差异）。

典型形态：

```
「会议开完了。你现在最想先做的是一件什么小事？」
  亲手画一条新的路线  → 士气+几，信任+几
  先让人知道          → 信念+几，信任+几
```

两个选项都是好的，只是好得不一样。玩家不需要权衡，因为**没有需要放弃的东西**。

### 1.7 节奏与阅读体验

| 问题 | 实测 |
|---|---|
| 章节长度 | 每章 277–374 步，无中场、无分段 |
| 章末卡片 | 显示三个数字，**4.2 秒后自动进入下一章**，不给玩家消化时间 |
| 快进 | `S` / `Ctrl`，固定 26ms/步（≈38 步/秒） |
| 已读判定 | **不存在**。快进会无视是否读过，一律冲过去 |
| 跨章保护 | **不存在**。`endChapter` 只把 `running` 置 false，快进定时器仍在跑；章末卡 4.2 秒后自动开局下一章，快进随即继续 → **按住 Ctrl 或开着 `S` 可以一路冲穿全剧** |
| 史料解锁 | 章末 `endChapter` 里 `forEach(unlockArchive)` 一次性入库，章内无感 |
| `note` 史料小注 | 全剧仅 **6** 条（81 条档案 vs 6 条内联提示） |
| 首屏"继续" | 只显示"已走 N 章"，不显示停在哪一章哪一句 |

### 1.8 资产与加载

- 已跟踪 76.8 MB；立绘 PNG 55.9 MB、单张最大 446 KB。
- 背景 / CG 单张 SVG 460–600 KB。
- 立绘按需加载（先试 PNG 再回退 SVG），但**插画画廊会一次性挂载 50 张 SVG**（约 20 MB）、**人物图鉴会一次性挂载 35 张 PNG**（约 10 MB），首次打开有卡顿风险。
- `tmp/` 本地 655 MB（已 gitignore，未跟踪，但会挤占工作区）。

## 2. 诊断：按影响排序的八个问题

### P0-1 三条数值是死的

最显眼的"游戏性符号"不参与任何逻辑。玩家学会忽略它，之后就再也不会看右上角。**这是全部问题里唯一一个"玩家在 10 分钟内就会得出负面结论"的。**

### P0-2 后果不累积

92 个非仪表 flag 里 43 个无人读取；有反应的选项也在 100 字内收束。20 章之间没有任何"上一章的你还在这里"的痕迹。

### P0-3 一半的选项没有代价

52% 的选项是"挑哪种奖励"。没有取舍就没有决定，没有决定就没有代入。

### P1-4 抵达终局的反馈几乎为零

3.5–5 小时的投入，换一屏两段散文 + 一个三字评语。终局没有回执、没有曲线、没有"我一路上做了什么"，也就没有任何可分享的产物。

### P1-5 真分支只覆盖 20% 的章节

ch09–ch12 之外全是直线。即使有 `if`，也只是插入几句话再合流。

### P1-6 快进会毁掉体验，且无法安全重玩

没有已读概念 ⇒ 二周目无法用快进跳过熟悉部分（因为会连着没读的一起冲掉）；跨章不停 ⇒ 一次误触 `S` 可能让你丢掉整章。

### P2-7 长跑没有分段

每章 300+ 步一口气走完，章末卡 4.2 秒自动关。玩家没有"歇一下"的节拍，也没有"这一章我走了一半"的进度感。

### P2-8 收集与内容脱节

81 条档案在章末批量入库、280 张立绘只按人物解锁、`note` 只有 6 条。收集系统存在，但玩家感受不到"我在收集"的过程。

## 3. 改造方案

### 3.0 总纲

把现在的「选项 → 三个数字 → 忘掉」，改成：

```
选项 → 记在人身上（名册）+ 记在物身上（意象账）
     → 后面每一章都会回响一次
     → 终章交出一份"我这一路做了什么"的回执
```

**红线不变**：史实结论、会议决议、人物牺牲、会师结局一律不动。玩家改变的是「这支队伍走到最后时是什么样子」，以及「你记住了谁」。

四条改造轴，按性价比排序：**A（数值语义化，半天）< D（终局回执）< B（名册）< C（节奏与重玩）**。

---

### 轴 A：让数值说话（成本最低，观感提升最大）

#### A1 给三个数值配"人话翻译"

三条数值条旁边（或下方）加一行随区间切换的小字，玩家每看一眼就知道队伍现在是什么状态：

| 数值 | ≥75 | 45–74 | ≤44 |
|---|---|---|---|
| 士气 | 队伍还愿意跟着走 | 走得动，但没人说话 | 掉队的比说话的多 |
| 信任 | 有话肯当面说 | 有话说一半 | 各走各的 |
| 信念 | 知道为什么走 | 只知道往哪走 | 只是在走 |

成本：`src/engine/engine.js` 的 `syncMeters()` + `css/style.css` 各加十几行。**这是全方案里唯一一个"改 20 行代码、立刻改变玩家对游戏的第一印象"的改动。**

#### A2 选项的后果要看得见

`pickChoice()` 之后弹一行短提示，例如「士气 +5　信任 +4」。现在的反馈只有数值条的 430ms 闪光，玩家根本来不及对上刚才做了什么。

#### A3 让三条数值真的进入剧本（关键）

在每章至少安排 **2 处**由数值门控的段落：

```js
{ t: 'if', cond: { var: 'morale', op: '<=', value: 40 }, then: [
  { t: 'narr', text: '夜里点过一次名。少了一个人。没有人问是谁。' }
]},
{ t: 'if', cond: { any: [
  { var: 'morale', op: '>=', value: 70 },
  { var: 'trust',  op: '>=', value: 70 }
]}, then: [
  { t: 'say', who: 'wu_laoliu', face: 'smile', text: '今天有人唱歌了。走得不快，但没人掉队。' }
]},
```

每处只需 2–4 行，20 章合计约 40 处、约 150 行文本，就能让"数值"从装饰变成玩家能亲眼看到的因果。**这是把 P0-1 从"死"变"活"的最小代价路径。**

---

### 轴 B：名册与意象账（本方案的核心机制）

#### B1 队伍名册 —— 把"人"变成存档单位

本作的题材决定了它最有力的机制不是数字，而是**人**。8 个虚构人物（小满 / 李铁柱 / 何晓梅 / 郭大娘 / 石柱 / 阿月 / 吴老六 / 三娃）已经贯穿全剧，但玩家和他们的关系完全不留痕。

**设计：不改史实，只记关系。**

- 每个人的**生死与结局保持既定**（小满走到会宁、石柱在娄山关牺牲……），这部分是史实级红线，不动。
- 玩家的选项改变的是**你和这个人之间发生过什么**：

```js
// 剧本侧只写这一行（零 DSL 扩展）
{ t: 'set', var: 'flag.bond.shi_zhu', op: '+=', value: 1 }
{ t: 'say', who: 'shi_zhu', text: '……你把鞋给我了。' }
```

- 引擎侧新增一个 **队伍名册面板**（挂在 `Tab` 状态界面里），扫描所有 `flag.bond.*` 聚合呈现：

```
石柱 · 江西兴国 · 同行
  你替他背过三天枪
  你把最后一双草鞋给了他
  —— 娄山关，一九三五年二月
```

**为什么选"命名约定 + 引擎聚合"而不是新增 DSL step**：零契约变更、`tools/lint-story.js` 不用改、20 章可以并行开工。这是刻意压低成本的取舍。

#### B2 意象账 —— 七个贯穿意象要真的能被"携带"

SPEC 已定义 7 个贯穿意象：**号 / 铜顶针 / 铜锅 / 草鞋 / 门板 / 地图 / 火**。现在它们只是文本。改成可追踪：

| 意象 | 现在 | 改造后 |
|---|---|---|
| 铜顶针 | ch01 拿到（`flag.thimble`），ch20 决定还给谁 | 全程可查"顶针现在在谁手里"，终章按持有者生成不同收束 |
| 军号 | `first_bugle` | 记"你这把号吹响过几次"，终章显示 |
| 草鞋 | 只是描写 | `flag.shoes_given` 记"你送出过几双" |
| 门板 / 地图 / 铜锅 / 火 | 只是描写 | 各给 1 个计数 flag，终章汇总 |

终章据此生成一段**只有你才有的收束文本**，而不是三档模板。

#### B3 跨章回响 —— 新增写作硬指标

给剧本 agent 的新规则（写进 `docs/STORY_BRIEF.md`）：

1. **每章至少 3 处 `if`，其条件必须引用往章的 `flag.*`**（不是本章的）。
2. 从现有 92 个 flag 里挑出 12 个"主线 flag"，要求**终局前每个至少被读 2 次**：`remember_names`、`thimble`、`first_bugle`、`orange_paid`、`carried_straggler`、`into_company`、`keep_frame`、`marsh_saved`、`sanwa_saved`、`bugle_warm`、`captives_treated`、`ch19_words_to_mei`。
3. 每章至少 1 处回响写成"具体的一个人的一句话"，而不是抽象抒情。例：

```js
{ t: 'if', cond: { var: 'flag.remember_names', op: '=', value: true }, then: [
  { t: 'narr', text: '念到第七个名字的时候，小满停了一下。' },
  { t: 'narr', text: '那是在于都留下的一个人。他还记得。' }
]}
```

#### B4 把一半的"无代价选项"改成真取舍

现状 31/60 选项没有任何负向效果。目标：**降到 10/60 以下**。

改造手法（不改变历史结论，只改变代价落在谁身上）：

```
现在：「把干粮全留下」hope+5 trust+4  ｜  「记名字」hope+6 trust+3
改成：「把干粮全留下」hope+6 trust+4 morale-3   ← 你自己饿着
      「记名字」  hope+6 trust+2             ← 没有代价，但收益更小
```

规则：**每个选项至少要有一项代价**（数值代价或名册代价），让玩家在"我保住了什么"和"我失去了什么"之间做选择。

### 轴 C：让 3.5 小时读得下去

#### C1 已读集合 + 三种快进

这是重玩体验的地基，也是当前最容易误解成 bug 的地方。

```js
VN.G.read = { ch01: { '<step指纹>': 1 } }   // 指纹 = t + who + 文本前 8 字，章节编辑不失效
```

| 操作 | 现状 | 改造后 |
|---|---|---|
| `S` | 无差别快进 26ms/步 | **跳到下一个选项**（结构内容全保留） |
| 按住 `Ctrl` | 无差别快进，跨章不停 | **只快进已读段落**，遇未读自动停下并提示"这里你还没读过" |
| `endChapter` | 快进定时器继续跑 | **强制 `setSkip(false)`**，堵住"一路冲穿全剧"的洞 |

#### C2 章末卡改成"给你 20 秒"

去掉 4.2 秒自动跳转（或延长到 20 秒并显示倒计时）。卡片内容升级为**本章回执**：

```
第七章 完 · 遵义会议
  士气 62 → 66  ▲4      信任 58 → 55  ▼3      信念 61 → 68  ▲7
  石柱：同行 → 负伤
  你亲手画了那条新路线
  本章称号：把话说透的人
```

#### C3 每章分三幕

用现有的 `title` step（全剧已有 151 个）在章节内标出**幕**的边界，配合一个"本章进度 2/3"的指示，把 300 步切成三段可消化的长度。

#### C4 史料逐条解锁（把 81 条档案变成集章）

- 把 `note` 从全剧 6 条扩到**每章 3–5 条**（约 70–90 条）。
- 读到 `note` 时飘一枚"史料印章"动画，同时把该条档案标为已解锁。
- 史料档案界面显示"本章 3/5 条"，制造"读完这一章我想把剩下的也找齐"的动机。

---

### 轴 D：让读完的人有东西可拿

#### D1 终局回执页（本作最有可能被分享的产物）

把 `showResult()` 从"一屏散文"改成一份**个人行军档案**：

1. 终局评语（保留现有三档，措辞不变）
2. **三数值 20 章折线图**（Canvas 手绘，无依赖）
3. **逐章回执列表**：章名 / 你的关键选择 / 当时三数值
4. **名册终态**：8 个人各自的结局 + 你为他做过的事
5. 一行统计：走过的章 / 相遇的人 / 史料档案 / 解锁插画
6. **「复制为文字」按钮**：把上面全部转成一段纯文本写入剪贴板（`navigator.clipboard`，本地操作，无网络请求，符合零依赖红线）

#### D2 结局图鉴

三档结局全部可收集，未获得的显示「还有 N 种收束」。配合轴 C 的已读快进，二周目的成本从 4 小时降到约 40 分钟。

#### D3 章节称号（不是分数）

每章末给一个短称号（"把话说透的人"/"走在最后的人"/"先扔自己东西的人"），称号按本章数值变化与名册变化生成。称号写入全局进度，章节选择界面里每章下面显示你拿到过的称号——这是"再走一遍会不会不一样"的钩子。

#### D4 首屏"继续"要具体

标题画面的「继续征途」现在只写"已走 N 章"。改成「第七章 · 遵义会议 · 上次停在 132/330 步」，玩家才知道点下去会回到哪里。

## 5. 明确不做的事

| 不做 | 原因 |
|---|---|
| 加战斗 / 资源管理 / 数值 RPG | 与"史实结论不可变"的契约冲突，且会稀释叙事 |

| 引入任何外部依赖、CDN、字体、网络请求 | `docs/SPEC.md` §0 |
| 把三条数值改成影响结局走向 | 会让"走到会宁"变成可失败，破坏题材 |
| 为一个机制新增大量 DSL step 类型 | 契约变更成本高；本方案刻意用命名约定替代（见 B1） |
| 给 `choice` 加倒计时 | 与"慢慢读"的基调不符 |

## 6. 风险

1. **第 3 批是主要成本**（20 章 × 新增内容），且需要 story agent 理解"回响"与"代价"两条新规则。建议先做 **1 章样板（推荐 ch05 或 ch15，篇幅适中）**，验收通过后再铺开。
2. **已读指纹依赖文本内容**。若某章被大幅改写，旧指纹会失效，玩家会被当成"没读过"。可接受（退化方向安全：只是不能快进）。
3. **`flag.bond.*` 是命名约定，不是契约**。写错名字不会报错，只会静默不出现在名册里。建议在 `tools/check.js` 里加一条：扫描 `flag.bond.*` 的 key，与 `src/data/roster.js` 的 8 个人物 id 对照，出现未知 id 即失败。
4. **Canvas 折线图**要遵守 `--u` 缩放单位，否则在不同分辨率下会错位。
