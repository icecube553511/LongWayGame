# 制作规范（项目级总纲）

> 由 `/root` 维护，**冻结**。任何 agent 不得修改本文件；要改规范 → 发消息给 `/root`。
> 本文件管的是**「资产怎么做、怎么审、怎么收口」**；`docs/SPEC.md` 管的是**技术契约**（目录 / DSL / id 表 / 验收）。
> 两者冲突时以 `SPEC.md` 为准；本文件与某一族专项规范（`CG_DESIGN.md` / `BG_DESIGN.md`）冲突时以专项为准。
>
> **新 agent 从这里开始**：先读 `AGENTS.md` §1 的必读顺序，再读本文件的 §1–§3；
> 真正动手前读 §4（提示词纪律）与对应资产族的专项规范。

## 0. 一句话

这个仓库里的每一张图都要能从**一条命令**重新造出来、能过**一条命令**验收、
并且**换一个 agent 来做也是同一个结果**。做不到这三点的做法，无论画面多好看都不进仓库。

## 1. 三条总原则

| 原则 | 含义 | 违反的表现 |
|---|---|---|
| **零构建 / 零依赖 / 零网络** | `file://` 双击 `index.html` 就能玩；运行期不联网、不 fetch、不加载外部字体与图片 | 玩家第一次打开白屏、控制台报 CORS |
| **边界** | 只写自己名下的文件；id 表与冻结文件只能由 `/root` 改 | 两个 agent 同时改一个文件互相覆盖；契约被静默改掉 |
| **每次改动都要同步到 git** | 提交 + 推送到远端；推送失败要重试并如实记账 | 成果只在本地工作区或草稿分支上，别人拿不到（见 §9） |

## 2. 资产的标准管线（四条线，结构完全一样）

```
清单（id / 场景描述 / must / avoid）      ← 唯一的提示词来源，冻结在 src/data/*.js
   └─ node tools/xx-art.js               生成原始图 → tmp/xx-raw/
        └─ python tools/xx-post.py       裁切 → 调色 → 压框/暗角 → assets/generated/xx/<id>.png
             └─ src/engine/engine.js     候选回退链：位图 → 矢量兜底 → 静默降级
                  └─ node tools/check.js 闸门：id 齐、位图存在且是完整 PNG、体积过档
```

| 资产族 | 清单 | 生成 | 烘焙 | 成品 | 专项规范 |
|---|---|---|---|---|---|
| 立绘 600×900 | `src/data/characters.js` | `tools/neko-art.js` | `tools/neko-post.py` | `assets/generated/chars/{id}_{face}.png` | `ART_DIRECTION.md` §1 / §2 |
| 重要事件插画 1920×1080 | `src/data/cg.js`（清单就叫 `cg.js`，与背景的 `bgart.js` 命名不同，是历史原因） | `tools/cg-art.js` | `tools/cg-post.py` | `assets/generated/cg/{cgId}.png` | `CG_DESIGN.md` |
| 场景背景 1920×1080 | `src/data/bgart.js` | `tools/bg-art.js` | `tools/bg-post.py` | `assets/generated/bg/{bgId}.png` | `BG_DESIGN.md` |
| 群众印章（贴图素材） | `tools/neko-crowd.js` 的 `POSES` | `tools/neko-crowd.js` | `tools/neko-crowd-post.py` | `art/ui_00_crowd_stamps.js`（base64）→ SVG 背景用 `<use>` 复用 | `ART_DIRECTION.md` §2.3.1 |

**这套规范本身也要能验收**：`node tools/check-assets.js` 会把本文件里最容易违反、
又完全能用机器判定的几条挑出来跑 —— 规范文件与交叉引用是否齐备、群众印章的变体数量够不够、
有没有把同一张图重复登记成两个名字。它必须出现在任何「交付前必跑」的清单里。

**共同的硬规矩**：

1. **不许手工塞图**：`assets/generated/**` 与 `art/ui_00_crowd_stamps.js` 都是生成物，
   只能由上面的脚本写。想改画面 → 改提示词或调色参数，重跑管线。
2. **原始图必须留着**（`tmp/**-raw/`）：换调色参数、换烘焙尺寸时要能重烘焙，不必重新烧额度；
   `--force` 重出时旧图会自动备份到 `tmp/**-raw/prev/`。
3. **矢量兜底不许删**：`art/scenes_*.js` / `art/portraits_*.js` 画的 SVG 是位图缺失时的兜底，
   引擎的回退链永远不能出现"什么都没有"的画面（`SPEC.md` §4.4）。

## 3. 格式与体积档（硬性）

| 文件性质 | 上限 | 依据 |
|---|---|---|
| 纯矢量 SVG（无内嵌位图） | **400 KB** | 控制碎多边形数量 |
| 含内嵌位图素材的 SVG | **640 KB** | 贴图字节另算（群众印章、行军小人） |
| 立绘 PNG（600×900 RGBA） | **512 KB** | 单人胸像 |
| 背景 PNG（1920×1080） | **1280 KB** | 背景每章都在场、30 张一起加载，比插画更该克制 |
| 插画 PNG（1920×1080） | **1536 KB** | 细节量比背景高一档 |

**唯一的自检命令**（末行必须是 `超过本档上限的文件数 = 0`）：
`docs/ART_DIRECTION.md` §4.4 那一行 `node -e "…"`，改了任何烘焙参数后都要跑。

超档时的**允许做法**：让生成端出更平的画面（改提示词）、重烘焙时按调色板量化
（`cg-post.py` / `bg-post.py` 自带兜底：量化到 256 色，只丢噪点、不模糊、不缩尺寸）。
**不允许**：删掉画面里的人、把 1920×1080 缩成小图、用 JPEG 顶替 PNG。

## 4. 提示词纪律（出图 agent 必守）

1. **风格头统一**：出图脚本里的 `STYLE` 段是全仓库共用的一段话（低多边形刻面、左上硬光、
   禁渐变/禁线框/禁写实、固定调色板）。**不许各写一套**；要改风格头 → 找 `/root`。
2. **条目只写画面，不写禁令**：`prompt_en` 写场景、构图、光源；禁令一律进 `avoid`，
   由脚本统一拼 `AVOID: …`（并逐条去重）。
3. **`must` 4–6 条**：这张图「一眼必须认得出」的东西。复核时逐条对，缺一条就是不合格。
4. **光照纪律**：画面里**只允许描述中点明的光源发光**（火把、油灯、枪口焰……）。
   没写的光源不许亮 —— 这是夜景图最容易崩的地方。
5. **群像变体硬要求**（`ART_DIRECTION.md` §2.3.1）：同一姿态的多张变体必须是「看得出来是不同人」——
   体态、年龄、脸型、神态分开，**军装的磨损程度也要分开**（补丁 / 破口 / 褪色 / 泥污 / 缺扣 / 缠布条）。
   并排站着的人一律**点名取用**具体印章，不靠随机从池子里挑。
6. **先看提示词再出图**：`node tools/xx-art.js --only <id> --dry-run` 打一遍全文，确认无误再发请求。
7. **重出要有理由**：同一张图最多抽 3 次；仍不合格就在报告里写清「哪里不合格、试过什么」，
   不要靠反复抽卡掩盖提示词本身的问题。

## 5. 抠底与透明（踩过的坑）

同一个出图端点**可能返回两种格式**：洋红底 RGB，或**自带透明通道的 RGBA**（实测同一次任务里混着来）。
抠底脚本必须**先认 alpha，再退回洋红键色**：

* 先看四角 alpha：接近全透明 → 直接用它自带的蒙版裁包围盒；
* 否则按四角取键色扣洋红。

**为什么必须这样**：RGBA 送进只认洋红的脚本，`.convert("RGB")` 会把透明压成**黑色**，
再拿黑色当键色 —— 制服、靴子、头发这些暗部会被整片打成透明，人身上出现「窟窿」，而且不报错。

## 6. 程序化素材与 AI 素材混用（踩过的坑）

仓库里有两套「画人」的办法：`art/geosvg.js` 的程序化 `GEO.humanoid()`，以及
`art/ui_01_crowd_root.js` 覆盖后的 **AI 印章**。**两者的人体比例不同**，混用时坐标一律要重新核对：

* 任何**按旧版程序人物身高写的道具坐标**（担架、扁担、背包、手部物件……）在人物换成印章后都会错位。
  `bg_stretcher` 就是这么坏的：本该扛在肩上的担架落到了四个人小腿的高度，画面上表现为一块**悬空的灰板**。
* 排查办法：把这一景渲出来（`node tools/shot-one.js assets/generated/bg/<id>.svg`）**放大看人物与道具的接触点**，
  而不是只看构图对不对。
* 修法二选一：把道具坐标改到印章的实际高度（肩 ≈ 人物高度的 0.78），或者**让道具由印章自己承载**
  （担架队就是这么改的：提示词写明「肩上扛着担架的一头」）。

## 7. 叙事画面、动效、与「不要立绘」的句子

1. **叙事画面**：有一类 `bg_*` 不是地理场景，而是「一面画」（例：`bg_bullets_3/2/1` 三颗子弹、
   `bg_black` 全黑）。规则见 `ART_DIRECTION.md` §3.1：主体唯一、底是纯黑、
   **多张之间主体的位置必须一致**（少的是「被打掉的那一发」，不是「图排重新居中」）。
   这类画面**不出位图**，靠程序化 SVG；`backgrounds.js` 的 `noBitmap` 与 `bgart.js` 的 `svgOnly`
   必须同改，`tools/check.js` 会核对。
2. **动效**：`cg` 步的 `motion` ∈ `zoom-in`（默认）/ `pan-left` / `pan-right` / `still` /
   **`impact`**（进场先挨一下再沉下来，给炮击、爆炸、撞击那一刻用）。新增动效要同时改四处：
   `css/style.css` 的关键帧、`src/engine/engine.js` 的 `CG_MOTIONS`、`tools/check.js` 的白名单、
   以及 `docs/SPEC.md` §2.1 与 `CG_DESIGN.md` §3 的枚举。
3. **不要立绘的句子**：`say` / `think` 可带 `noPortrait: true`（`SPEC.md` §2.1）。
   引擎有「说话的人必须在台上」的不变式，会把说话人的立绘补上场；当画面主体是别的物件时
   （例：三颗子弹），必须**显式声明** —— 不能靠「画面类型」去猜。
4. **硬切**：`{t:'bg', id:'bg_black', fx:'black'}` 是「整屏硬切到黑」的标准写法；
   要配情绪音效（如眩晕）就在其后加 `{t:'sfx', id:'…'}`。

## 8. 评审规范

### 8.1 独立性（最容易被绕过的一条）

* **自评不算验收**（`docs/reviews/R1-SELF-CHECK.md` 立的规矩）。判定者与被判者不能是同一个 agent；
  做不到时，报告**必须在文件头写明「自评 · 不是独立评审」**，并说明为什么。
* 评审 agent **不修东西**：只产出判定 + 可执行的修法；改由 owner 来做，改完再复判。
* 评审 agent **不许改仓库**（源码 / 剧本 / 图片 / `tools/` / `docs/`），也不做 git 操作。

### 8.2 取证方法（三条硬教训）

1. **缩图不能用来判「块面」**：640 宽的缩图会把多边形面的边界抹平，把块面画误判成「写实 / 连续渐变」
   （实测 5 张被误判，逐张按原生分辨率复核后全部推翻）。判风格要用
   **原生分辨率的局部裁剪（600–900 px）**，不是整图缩图。
2. **不要把大图塞进对话**：一次塞多张 1.4 MB 原图会直接撑爆请求体
   （`413 Payload Too Large`）。逐张看、看完就写判定；要看全貌就用
   `python tools/cg-sheet.py tmp/x.jpg`（JPEG 拼版，26 张一屏约 500 KB）。
3. **判定必须有证据**：截图路径 / 命令输出 / 画面里的具体位置。「我觉得」不算。

### 8.3 判定档位与修法

| 判定 | 含义 |
|---|---|
| `PASS` | 判据全过 |
| `FAIL` | 有硬伤（破红线 / 图文不符 / 史实错 / 大特写正脸） |
| `PARTIAL` | 可用但有明确可改处 |

每条 FAIL / PARTIAL 必须给**可执行的修法**：画面问题给一句能直接粘进
`node tools/xx-art.js --only <id> --extra "…"` 的**英文修正句**；文字问题写「原句 → 改句」；
落点问题写「移到第 N 步」。**「再低饱和一点」这种没法执行的建议等于没提。**

## 9. git 纪律（用户立的长期规则）

1. **每一次改动都要提交并推送到远端**；不许把成果只留在本地工作区或草稿分支上。
2. 子 agent 不跑 git（避免抢 `index.lock`），由组长在每组收工与整轮收口时各推一次。
3. 本机 `github.com:443` 的 TLS 握手**间歇性**失败（`schannel: failed to receive handshake`），
   而同一时刻 `https://api.github.com` 走同一代理返回 200 —— 代理没坏。用下面的参数并重试：

```powershell
git -c http.version=HTTP/1.1 -c http.postBuffer=524288000 `
    -c http.lowSpeedLimit=0 -c http.lowSpeedTime=999999 push origin <分支>
```

4. 推送失败必须重试（间隔 20–30 秒，通常几轮内会过），并把失败原因与当时的 `git status`
   写进报告，**不许吞掉**。
5. 提交前 `git status --short` 自检：不要提交 `tmp/` 下的东西（已在 `.gitignore`）；
   一个改动一个 commit，message 写清「改了什么、为什么、怎么验证的」。
6. **多路并行时先看 `git branch -v`**：本仓库长期有多个 agent 同时工作，曾发生过
   「提交落在别人的分支上」「远端被别人的推送顶掉」的情况 —— 推送前后都用
   `git ls-remote origin <分支>` 核对远端实际指向。

## 10. 事故与教训（可复用清单）

| # | 现象 | 根因 | 规矩 |
|---|---|---|---|
| 1 | 位图插画**整段不显示**（图已加载、图层不亮） | 点亮图层放在 `requestAnimationFrame` 里，而无头浏览器会饿死帧调度、**后台标签页会被浏览器暂停渲染** | 关键显隐一律**同步**执行（强制回流 + 直接加类）；rAF 只能当幂等兜底 |
| 2 | 插画**有时不上屏** | 用游离的 `new Image()` 当替身探针，大图解码期间对象被回收 → `onload` 永不触发 | 预载/回退**直接用可见的 `<img>`**，借它自己的 `onload`/`onerror` 逐级回退 |
| 3 | 闸门是绿的，玩家看到的却是兜底图 | 闸门只看「文件名在不在」，而烘焙写到一半会留下 0 字节 / 截断的 PNG | 判定「图已生成」必须查**文件头 + 大小**，不只看文件名 |
| 4 | 人物暗部被打出窟窿，且不报错 | 上游返回 RGBA 透明底，抠底脚本按洋红键色处理，把透明压成的黑色当键色 | 抠底**先认 alpha**（§5） |
| 5 | 背景里出现悬空的灰板 | 程序化道具的坐标是照旧版程序人物写的，人物换成 AI 印章后没跟着改 | 混用两套人物系统时**重新核对接触点**（§6） |
| 6 | 一排人长得一模一样 | 印章池里只有 2 张，而场景里并排 4 个人 | 变体要够多，并排的人**点名取用**（§4.5） |
| 7 | 画面与图注打架（例：图注写「没有一支火把」，画面点了一整圈火把） | 提示词与条目 `avoid` 冲突 | 出图前 `--dry-run` 读一遍全文；**图注与画面必须互相印证** |
| 8 | 全书最重要的人物伏笔在小角色身上提前兑现 | 画面画了「他吹响了号」，而正文写「他还吹不响」 | 出图前**读该章该拍的正文与人物设定**，别只看图注 |
| 9 | 两个 agent 互相覆盖文件 | 并发改同一文件 | 只写自己名下的文件；改前先看 `git status` |
| 10 | 清理挂死进程误伤同伴 | 按「最近启动的 node 进程」批量杀 | 只杀自己启动的 PID，先核对命令行身份 |
| 11 | 评审 agent 收不到任务书 / 一次塞太多图崩掉 | 消息投递故障 / 413 | 任务落到文件里由对方自己读；图用缩图或局部裁剪（§8.2） |

## 11. 契约同步清单（改一处，要连带改哪些）

动以下任何一项，都要把**所有**相关文件一起改，否则闸门会红、或者玩家会看到坏画面：

| 你要动 | 必须同步 |
|---|---|
| 背景 / 人物 / 插画 / 音效 **id 表** | `src/data/*.js` · `docs/SPEC.md` 对应表 · `tools/check.js` 白名单 · `tools/lint-story.js` 白名单 · 画廊 `src/engine/gallery.js` |
| 新增一条**插画** | `src/data/cg.js` 条目 · `node tools/cg-art.js --only <id>` 出图烘焙 · 剧本里插改 `{t:'cg'}` · `CG_DESIGN.md` 有新写法时同步 |
| 新增一条**背景** | `src/data/backgrounds.js`（含 `noBitmap`）· `src/data/bgart.js`（含 `svgOnly`）· `art/scenes_*.js` 的程序化兜底 · `ART_DIRECTION.md` §3 |
| 新增**动效 / 字段** | `css/style.css` · `src/engine/engine.js` · `tools/check.js` · `docs/SPEC.md` §2.1 · 对应专项规范 |
| 新增**音效** | `src/engine/audio.js`（程序化合成）· `src/data/backgrounds.js` 的 `audioIds` · `docs/SPEC.md` §5 · `tools/lint-story.js` 的 SFX 白名单 |
| 改**体积档 / 命名规则** | `ART_DIRECTION.md` §4.4 · 对应 `tools/xx-post.py` 的上限常量 · `tools/check.js` 的判定 |

**改完必跑**：`node tools/check.js` + 上表中受影响的那条验证命令；改契约本身要先找 `/root`。
