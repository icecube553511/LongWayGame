## 4. 发现的唯一异常：探针的 CG 统计会漏记（不是游戏缺陷）

`tools/e2e-run.js` 报告 ch05「CG 0」，据此打印了「全程没用 CG 的章节：ch05」。
**这个结论是错的。** 我用另一个探针直接停在 ch05 的 cg 步上读 DOM：

```powershell
node tools/e2e-steps.js ch05cg2 "ch05|until:VN.state.blockKind=='cg'|note:document.getElementById('bg-a').getAttribute('src')|note:document.getElementById('bg-b').getAttribute('src')|note:getComputedStyle(document.getElementById('bg-a')).opacity|note:getComputedStyle(document.getElementById('bg-b')).opacity"
```

输出（节选）：

```
过程: until: 推进 64 次
  | document.getElementById('bg-a').getAttribute('src') = "file:///…/assets/generated/bg/bg_stretcher.svg"
  | document.getElementById('bg-b').getAttribute('src') = "file:///…/assets/generated/cg/bg_liping.svg"
  | getComputedStyle(document.getElementById('bg-a')).opacity = "1"
  | getComputedStyle(document.getElementById('bg-b')).opacity = "1"
```

也就是说：**`cg/bg_liping.svg`（加强过黑边暗角的插画版）确实被加载进了可见层、opacity 为 1**，
插画字幕 `路要往哪边走，得当面说出来。` 也已经上屏（另一次探针读到 `#cg-caption` 的文案就是它）。
`tools/e2e-run.js` 的 `sampleBg()`（`:86-94`）要求「该层带 `.on` 且 opacity > 0.5」才记一笔，
而 ch05 这一处是 `bg` 步与同 id 的 `cg` 步**背靠背**触发两次 `setBg`（剧本 `ch05.js:58-59`），
双缓冲交叉淡入期间两层同时满足/同时不满足该判据，于是这一笔被漏记。

**结论**：
* 对玩家：**没有问题**，ch05 的插画正常渲染。
* 对工具：`e2e-run.js` 的 CG 列与末尾那句「全程没用 CG 的章节」**会漏报**，
  把它当"每章都有插画"的门禁会漏判 → 记为下一轮候选（属 `tools/` 区，本轮不改）。
* 存疑未结：`ch05.js:58-59` 这种「同 id 的 `bg` 步紧跟 `cg` 步」会让两次 `setBg` 在同一帧内叠加，
  双缓冲交换是否存在"插画被前一张背景换回去"的竞态，**本轮没有定论**（探针的快进会放大重叠，
  不能代表真人点击的时序）。记为下一轮候选，不在此下结论。


**根因**：`tools/e2e-run.js:27` 的虚拟时间上限默认值是 `600000`，20 章合计要消耗的虚拟时间

于是**这条默认命令取不到任何结果**（`tools/e2e-run.js:218/225`）。
与 `PLAY` 批给每个选项加的停顿一致：每章 3 个选项，20 章累积下来正好把这 600 秒压垮。

**修复**（root 直接改，改动极小）：默认预算 `600000` → `2000000`，并同步用法文案。
修复后用**默认参数**重跑：

```

```

**这条的严重度比它看起来高**：`README.md` §3 把这条命令列为"全剧自动通关验证"，
它是这个仓库唯一能一次性证明"二十章都还能从头走到尾"的闸门。闸门默认参数失效，
等于后续任何人（或 agent）跑它都会拿到一个误导性的失败。
