## 2. 真浏览器：小注确实在屏幕上（这一条是新增证据）

```powershell
node tools/e2e-steps.js root-q05-field "ch05|until:document.getElementById('note-text').textContent.length>0|wait:900|note:JSON.stringify({txt:…,cls:…,disp:…,op:…,h:…})"
```

输出（原文，节选）：

```
状态: {"chapter":"ch05","frame":"11/312","step":"say","who":"wu_laoliu","text":"往西。", …}
过程: until: 推进 13 次 | … = "{\"txt\":\"1934年12月12日通道会议后，红军改向贵州前进，但北\",\"cls\":\"\",\"disp\":\"block\",\"op\":\"0\",\"h\":37}"
错误: 0 条
```

* `#note-text` 里装着的正是被搬过来的那条小注（这句对白是小满的「老六叔，我们到底往哪儿走？」，
  修复记录里的 27 处之一）；
* `#note-layer` 的 class 为 `""`（**没有** `hidden`）、`display:block`、文本高度 37px。
* `opacity` 读到 0 —— 与修复记录的 ④ 号控制实验一致：**探针环境里 rAF 不触发**，
  而引擎是在 rAF 里给 `#note-layer` 加 `.on` 的（`src/engine/engine.js:575`），
  所以 `opacity` 在探针里对**任何**写法都是 0，不能用作判据。
  `css/style.css:248` 写明 `#note-layer.on { opacity: .96 }`。

**为了拿到肉眼级证据**，我在同一帧手动补上 `.on` 类（等同于引擎 rAF 回调要做的那一步），
再截图：`tmp/e2e/root-q05-visible.png`（`JS 错误 0 条 | ch05`）。我自己看了这张图：

> 画面左下、对白框上方有一条带金色「史料」标记的小注框，内容是
> 「1934年12月12日通道会议后，红军改向贵州前进，但北上湘西与红二、六军团会合的原定战略方针
> 并未正式改变。12月18日，中央政治局在贵州黎平召开会议，才以决议形式正式放弃原定计划。」，
> 下方对白框里是小满的「老六叔，我们到底往哪儿走？」。

也就是说：**小注确实上屏了，而且与那句对白同屏** —— 这正是原问题"写完就被下一步抹掉"的反面。
